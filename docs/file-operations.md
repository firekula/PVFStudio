# 文件树操作（0.13.0）

左侧文件树和路径搜索结果支持右键“新建文件…”、“新建文件夹…”、“重命名…”和“删除…”。在导航区域按 F2 重命名、Delete 删除、Ctrl+N 创建文件。根节点可创建内容，不能重命名或删除整个 PVF。

输入的是 PVF 内路径，可用 `/` 分隔多级目录；路径统一为小写，拒绝 `..`、空段、无法用 CP949 表示或过长的名称。重命名不会覆盖已有文件/目录，也不允许将目录移动到自身内部。

## 编辑、引用与草稿

文件操作立即写入独立草稿清单；编辑器随后显示变更后的树。目录重命名和删除递归处理文件；重命名更新打开标签的路径和标题，保留正文、未保存编辑、编码和光标。删除前提示包含文件数及将放弃的未保存标签，确认后关闭受影响的标签。路径搜索、全文搜索和预览使用变更后的文件集合。

**脚本正文里的路径和列表引用不会自动改写。** 移动、重命名或删除被引用的 ANI、MAP、物品等后，应通过全文搜索检查引用和相应 LST 等配置，再导出。工具不推断编号或依赖关系，也不会自动给新建脚本添加索引。

UUID 容器中新建 ANI 使用空的经典二进制动画；常用配置扩展名在存在 stringtable.bin 时使用空 `B0 D0` 脚本。其余文件使用当前编码的文本模板。保存时按该文件原有的表示方式编译，新增字符串通过原字符串表追加机制处理。

PVF 目录只保存文件路径，没有空文件夹条目。空文件夹记录在工作区，重开后仍可继续创建文件；只有包含文件的目录才体现在导出 PVF 中。

清单格式 2 保存新增文件的内容、重命名的源条目、删除记录和空目录，仍绑定原包 SHA-256；一次原子替换提交相关元数据。旧格式 1 可继续打开，之后保存使用格式 2；旧版本程序不能读取格式 2。源包始终只读，导出才生成修改后的文件集合。

## 结构导出

ACT1、UUID、Legacy 分别按自己的布局写入：

- 存续条目保持原目录次序及原身份；重命名仅更换路径，新条目追加到目录。ACT1 / UUID 新文件分配未使用的 32 位文件编号。
- 重建目录长度和条目数量。保留原目录尾部/预留区字节，按需补齐；未改路径的原始字节继续保留。
- 按原物理顺序保留存续文件，移除已删除文件的数据，新文件追加在原有尾部数据之前。保留所有原始间隙和不透明尾部。
- 保留未修改内容的明文及补齐；ACT1 根据最终相对偏移重新计算 CRC，UUID 根据文件编号计算 CRC，随后加密并重算目录 CRC。
- Legacy 保留存续块头其他字段，更新绝对位置、长度和块链接；链接目标存续时重定位，目标已删除时链接回当前块，新块也使用自身链接。不能由 Legacy 字节变换表示的内容拒绝导出。
- 回读校验完整目录、条目、内容/适用 CRC、补齐、间隙、尾部及 Legacy 块链接，再提交新目标。目标拒绝覆盖；应用的备份导出流程继续适用。

只有正文替换时仍走原有保真导出，无修改时要求整包字节一致。结构导出不等于游戏运行验收；文件依赖和游戏侧使用效果由实际修改内容决定。
