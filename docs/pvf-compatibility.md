# PVF 格式兼容（0.13.5）

0.12.0 按文件内容自动识别容器，不依赖文件名或所在目录。原包始终只读；修改保存到草稿，导出保留原容器格式。

0.13.0 在这三类容器上加入文件及目录的创建、重命名和删除；相关清单、结构导出保真规则和四份真包验证见 [文件树操作](file-operations.md)。

| 容器 | 已验证样本 | 条目数 | 读取和导出 |
| --- | --- | ---: | --- |
| ACT1 `DNF_SCRIPT_PACK` | 原 ACT1 样本 | 48,343 | 原有功能继续支持，条目 CRC 初值为相对数据偏移 |
| Legacy 固定目录 | DNF_Single | 4,263 | 文本脚本编辑；保留预留目录、块头、链接、间隙和尾部 |
| UUID 经典容器 | 70S2 | 369,711 | 解密读取；保留 UUID、版本、文件编号、目录顺序、加密掩码和补齐；条目 CRC 初值为文件编号 |
| UUID 经典容器 | DOF86 | 666,933 | 大包进度、二进制脚本与经典 ANI 编辑；实际 ANI 草稿导出重开已验证 |
| UUID 经典容器 | 100 级样本 | 929,093 | 已验证读取、MAP / DGN 及引用资源预览；本样本结构导出和游戏加载尚未验收 |

UUID 目录探测零掩码和 `0x81A79011` 掩码，并用带文件数初值的完整目录 CRC 确认结果。零掩码分支由独立构造样本验证；70S2 真包验证使用后者。允许 UUID 格式中的重复文件编号，仍拒绝重复路径和重叠物理数据。

## 编码和二进制脚本

在“文件 → 打开编码”选择正文编码：DNF_Single 样本使用 **MS949 / CP949**，70S2 样本使用 **Big5**。全局正文搜索同样提供 Big5。编码按标签保存，重开工作区可恢复。

0.12.1 默认选择“自动（按 PVF 格式）”：ACT1 用 GBK，Legacy 用 MS949，UUID 用 Big5。这是已验证样本的默认值，并非任意内容的编码检测；可手动覆盖。恢复 Legacy 的旧 GBK 标签时，若原始字节存在可确认的韩文配置标签，会将该标签修正为 MS949，保留草稿字节、光标和滚动位置。

## DNF_Single 场景预览

0.12.1 补齐韩文 MAP/TIL/DGN 标签、背景图层与朝向、NPC/怪物/对象待机配置。解析器仅规范化用于预览的关键字，编辑器保留原始韩文正文、路径、字符串及导出内容。

资源选择支持客户端根目录、`ImagePacks2` 和 `Sprite`。DNF_Single 使用 `Sprite` 下的独立 IMG，工具可自动发现并按需读取，无需重新打包成 NPK。若旧工作区保存了其他版本的 NPK 路径，请在“选择资源目录”中改选 DNF_Single 或其 `Sprite` 目录，避免混用版本资源。

该真实样本包含 397 个独立 IMG；`map/hendonmyre/hendon_pub_pvp.map` 的 6 块地形、背景和 NPC，以及各 TIL 通行格已通过实际工作台验证。资源改变检测、缓存和重复路径诊断同样适用于独立 IMG。

该包唯一的 `dungeon/temp.dgn` 是 1×1 模板，没有 MAP 指定，MAP 也没有 `[dungeon]` 关联。工具显示布局及未关联原因，不将酒馆 MAP 自动认作模板房间。旧版形状码来自客户端的 16 项表（`0x594278`，使用点 `0x483278` / `0x48539C`），支持 `┼┾╀╄┽┿╃╇╁╆╂╊╅╈╉╋` 与对应方向位。

`B0 D0` 脚本通过同包 `stringtable.bin` 显示为标签、数字和反引号字符串。可以编辑数值、标签和字符串；新增字符串追加到字符串表，保留已有索引及原始字符串字节。脚本与字符串表草稿通过一次 manifest 更新共同提交，导出时一起写回。原始差异视图比较解码后的脚本。

投影使用 `#PVF_File`，整数为普通十进制，浮点数带 `f` 后缀，字符串使用反引号。字符串内支持 `\\`、`\``、`\r`、`\n`、`\t`、`\0` 转义。尚未解释的 token 显示为 `@类型(原始整数)`，无修改保存保留其类型和 32 位值；不会猜测链接或命令含义。保留原位置相同词项的字符串索引、重复索引和浮点位模式。

新增字符串必须能由该标签选择的编码无损表示，否则保存失败并保留原草稿。字符串表可能保留撤销脚本后不再引用的追加字符串；它仍是独立修改条目。

## 当前边界

0.12.3 增加经典二进制 ANI 解码、编辑及预览，86 样本中 402,701 个动画通过字节一致重编译，另有 493 个结构、指令或编码问题待支持，见 [二进制 ANI](binary-ani.md)。专用二进制 MAP/TIL 及未识别的 ANI 保持只读十六进制预览（最多显示 64 KiB），不会作为文本写回。已有 ACT1 文本资源预览继续适用；兼容扩展不代表新版所有动画、地图和副本都已支持可视化。

Legacy 样本包含 32 字节头、1028 字节目录槽（1024 字节路径和 4 字节绝对块偏移），数据块头长 24 字节。当前接受有效且逻辑长度与存储长度相同的块；其他块状态/压缩方式明确报错。原客户端 `DNF.exe` 的 `0x4F5210` 解密、`0x4F51C0` 加密按 16 位 word 交换字节并加减 `0x0C74`，零 word 特判，奇数末字节保持不变；该格式没有 ACT1/UUID 的条目 CRC。导出会回读、检查链接重定位、未改密文、间隙和尾部。

经典 UUID 的公开格式参考：[similing4/pvf 原始格式说明](https://github.com/similing4/pvf/blob/master/chunk.md)。实际支持以本地样本及回归结果为准。

## 验证

```powershell
.\gradlew.bat check :pvf-cli:installDist
python -B -m unittest discover -s validation -p 'test_*.py'
python -B validation/run_compatibility.py 'C:\Game\Script.pvf'

python -B tools/check_product.py --product 'pvf-product/build/product/PVFStudio-0.13.5' --archive 'C:\Game\Script.pvf'
```

`run_compatibility.py` 对原包全量读取，执行无修改重建、文本/二进制 token 数值修改、新增字符串、草稿重开和变长导出，再用独立 Python 实现核对所有条目的预期明文、CRC（适用时）、原始路径、目录不透明字节、间隙、尾部及源文件完整性。产物仅写入新建的 `build/compatibility/` 子目录。

2026-10-26 的三份真包合计 **422,317 个条目**通过上述验证；两份新增样本另外通过实际 IntelliJ 工作台的打开、编辑保存、全文搜索、导出重开及二进制只读检查。新增变体尚未执行游戏客户端加载验证，不能将编辑器回读等同于游戏运行验收。
