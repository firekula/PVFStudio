# MAP / DGN 可视化编辑器设计

日期：2026-10-26。基线：PVF Studio 0.13.5，提交 `61f8da6`。

状态：方案已选，设计待用户审阅。本文没有授权尚未确认的发布，也不代表产品功能已经实现。

## 1. 用户目标与已经确定的选择

用户希望把现有 MAP / DGN 预览升级为能够保存和导出的可视化编辑器，减少手工编写房间网格、资源路径、实体坐标与连接配置的工作。

明确要求：

- MAP 可以从当前目录及子目录添加 TIL，从全局列表添加被动对象、怪物，并添加动画、特效等已有配置能力。
- DGN 可以创建房间，为房间设置 MAP，编辑连接，设置起始房间和 Boss 房间。
- 先核实中途深渊房的机制，再把它纳入 DGN 设置。
- 用户已选择“完整可视化编辑页”，并要求类似 Android Studio，能够切换到代码编辑。

实现方提出的补充选择（不是用户已经逐项确认的要求）：

- 每个 MAP / DGN 标签右上角提供“可视化 / 代码 / 分屏”，默认可视化。分屏为可选辅助模式。
- 复用现有 Java / Swing / IntelliJ Platform 和场景渲染器，不引入新的桌面框架。
- 起点、Boss 和 MAP 保留原配置的多个候选，不把随机候选强制压缩成一个值。
- 修改共享 MAP 时显示影响提示，提供复制 MAP 后绑定当前房间的方式；直接修改原 MAP 是显式可选动作。
- 不执行游戏 AI、战斗、深渊召唤流程或服务器事件；可视化编辑的是实际配置，预览显示当前支持的初始视觉。

成功标准：用户可以用图形界面完成一份原生可表达的副本布局和房间内容修改，切到代码后看到准确的对应修改，再经现有草稿与导出流程获得可回读的新 PVF；没有编辑的配置保持原样。

## 2. 方案比较与选择

### 方案 A：主编辑区中的完整可视化页（用户已选择）

MAP / DGN 作为现有文件标签的一种编辑表面，拥有足够的画布空间、资源选择器和属性检查器。代码与可视化通过同一份 IntelliJ Document 联动。需要调整标签容器和会话状态，但适合持续增加编辑工具，也不会把主操作挤进已有的小预览面板。

### 方案 B：在右侧资源预览中增加编辑工具（未选择）

可以保留现有源码并排工作方式，容器改动较少；但房间网格、资源浏览、对象属性和地图会争用预览宽度，已有小窗口体验限制会加重。

### 用户补充：随时切回代码

采用 A，并保留显式的代码入口。可视化和代码是同一文件的两种视图，不是两份需要点击“应用”才能同步的配置。

## 3. 当前代码依据

- `pvf-preview/SceneScript.java`：TIL、MAP 地块与动画、移动区域的解析。
- `pvf-preview/EntityScript.java`：实体列表、普通/条件/特殊放置、装备和初始视觉；已识别特殊对象中的 hellparty 负载。
- `pvf-preview/DungeonScript.java` / `DungeonPreview.java`：多套 maze、拓扑、候选 MAP、起点/Boss、原生通路门和状态预览。目前没有完整深渊编辑模型。
- `pvf-product/.../PvfStudioFrame.java`：一个 Session 包含一个 IntelliJ Editor / Document，文档事件刷新预览；当前标签组件直接是 editor component，需要增加表面容器适配。
- `pvf-product/.../ResourcePreviewPanel.java`：Source 是当前文本及引用快照，Canvas 已有相机、缩放和平移，但当前命中结果主要是提示字符串，不能直接当编辑对象身份。
- `pvf-product/.../EditorSessionState.java`：保存文件、编码、光标、滚动与选中标签；新模式状态须向后兼容扩展。
- `pvf-workspace/PvfWorkspace.java`：草稿、文件结构操作、二进制脚本与字符串表成组提交。不能假设现有单文件 create/rename 已提供跨文件创建事务和撤销。

现有解析器只为读取服务，会忽略未知字段、去掉注释与源位置细节；不能把其对象重新序列化后整体覆盖原文。

## 4. 编辑表面与切换行为

### 4.1 文件标签

MAP / DGN 标签拥有一个持久 Session 容器，内部保留 IntelliJ Editor 实例和可视化表面。普通文件继续现有行为。一个虚拟路径只有一个活动文档，不因从 DGN 跳转 MAP 再创建重复编辑器。

右上角：

- 可视化：展示画布和属性；DGN 中显示布局，MAP 中显示场景。
- 代码：展示现有 IntelliJ 代码编辑器，继续原有语法着色、查找替换、差异和快捷键。
- 分屏：左侧代码，右侧可视化；可拖动分隔条。小窗口允许用户主动切回任一单视图，不能隐藏代码入口。

切换不保存、不重写原文、不清除撤销记录，不重新创建 Document；保留光标、代码滚动、画布相机、缩放与当前选择。编码改变、文件重命名和标签关闭经过原有 Session 生命周期处理。

DGN 中“编辑房间 MAP”会定位到该 MAP 的现有或新标签；DGN 标签保留选中房间和布局，提供返回来源副本的入口。分屏始终表示同一个文件；不会把 DGN 源码错误地与一个可编辑的子 MAP 画布放在同一文档身份下。

### 4.2 实时同步与错误状态

- 可视化操作通过 IntelliJ 写命令修改该 Document 的源片段；一项用户动作对应一个撤销单元。
- 代码变化后后台解析并刷新可视化，按文档版本隔离过期结果；快速输入做短暂合并，不能在 UI 线程扫描整个 PVF。
- 代码暂时不完整时保留原文与最后有效画面，显示“画面尚未同步”和具体错误；禁用依赖失效区域的写操作。其他可独立确定的区域可继续工作。
- 不允许拖动或属性编辑把旧模型回写到用户刚修改的新代码。提交前验证 Document 修改戳和源片段仍然匹配；不匹配则取消该操作并重新解析。
- 可视化选中项可定位代码片段；代码光标能匹配到已识别记录时，可定位/高亮画布对象。定位不强制改动用户的播放或相机状态。
- Ctrl+S、Ctrl+Z/重做、Diff 和导出作用于当前文件文档，不因焦点在画布或属性字段而失效。

## 5. DGN 编辑

### 5.1 布局与房间

- 支持现有多套 `[maze info]` 的切换、复制和新增；保留每套的任务/条件字段及原顺序。
- 网格显示空格、普通房间、起点候选、Boss 候选、深渊位置和诊断。创建房间采用点击空格；可扩展布局尺寸，受现有 50×50 上限约束。
- 删除房间时，在同一命令中删除它的普通/Boss MAP 指定记录、各类位置候选及相邻连接；若它是深渊位置，同步清除该布局的深渊位置引用，保留未使用的 MAP 文件。操作可撤销。
- 改变尺寸时不自动删除落在新边界外的房间；先显示将受影响内容，再由用户选择保留尺寸或明确裁剪。默认扩展向右/下，既有坐标不变。
- 零连接格与原生空格均可能编码为 AA。新房间在形成有效连接前可显示为待完成项；必须通过显式 MAP 指定或未完成操作元数据保留其身份，不能声称 AA 已成为游戏可达房间。导出时提示/阻止新增的不可达配置；已有教学单房间的 AA 起点按原规则处理。

### 5.2 MAP 关联

- 从 `map/map.lst` 搜索编号、路径与可获得的名称；使用当前 PVF 和草稿/未保存快照，不混用其他 PVF 的索引。
- 房间属性支持指定一个或多个普通 MAP、Boss MAP 候选。可明确选择固定单 MAP，也可保留多个候选或原有自动匹配方式。
- 把房间标成 Boss 点不会把一个普通 MAP 的怪物自动变为领主。界面同时展示 Boss MAP 关联，校验 MAP 类型与现有怪物类型，缺失时提示并可跳转编辑。
- 已有显式 MAP 与拓扑不符时，沿用现有“保留显式关联并给出诊断”的规则，不能悄悄换成文件名相似的 MAP。
- 首版选用已存在 MAP；需要独立修改时可复制已有 MAP 并注册新编号。从零生成全新的空 MAP 模板不是本次必需范围。

### 5.3 连接与起点/Boss

- 在相邻房间之间点击连线或通过左/右/上/下属性切换连接。图形工具建立/移除双向连接，同时更新两个房间的 greed 位。
- 不提供任意连向不相邻房间的“传送连线”；原有脚本中的非对称连接作为诊断保留，不能因打开可视化就自动修复。
- 起点、Boss 分别允许多个候选。默认操作是切换所选房间的候选身份，也提供明确的“只保留此点”。无 Boss 保留原生 `-1 -1` 表达。
- 检查越界、单边连接、起点缺失、起点到 Boss/深渊不可达、空候选和引用缺失。多候选按可选组合检查，不只检查当前预览方案。
- 新连接对应的 MAP 通路门坐标须可用；提供跳转到 MAP 的门位置编辑。更改 DGN 连接不擅自重写被其他副本使用的共享 MAP。

## 6. MAP 编辑与资源添加

### 6.1 场景操作

- 单击选中、拖动移动、属性精确输入、复制、删除；工具区明确区分选择/放置和平移。空格或中键平移，滚轮缩放，避免左键既移动相机又移动对象。
- 坐标使用配置的 X/Y/Z，视图换算复用现有 `y-z+120`、缩放、相机和图层视差。普通拖动修改 X/Y 并保持 Z；Z 在属性中修改。可选网格吸附不改变原本未吸附的坐标。
- 拖动期间只更新临时画面，松开后一次写入；Esc 取消。框选/多选不是首版验收必需能力。
- 命中遵循实际绘制顺序，支持切换重叠对象和从对象列表选中。粒子选择其工厂/发射器放置记录，不把运行时生成的每个粒子当作独立可编辑项。
- 复制、删除与移动使用源记录身份，不用“第几个被画出的精灵”充当配置索引；条件关闭、一个实体多部件、逻辑对象无视觉时仍能在列表中操作。

### 6.2 TIL

- “添加地块”默认递归列出当前 MAP 所在目录及子目录的 `.til`，支持搜索、缩略预览和 basic/extended 分类。
- 基础地块按原生横向序列插入/删除/替换/排序；扩展地块按基础列数分行显示，不能把 TIL 当成自由放置装饰。
- 追加/删除基础列时保留已存在地块的归属，预览并要求用户补齐受影响的扩展行；不静默丢弃不完整行。新生成的不完整扩展行需完成或撤销后再导出。
- 路径保存为相对于 MAP 的有效引用。不能从一个目录复制 MAP 到另一目录后仍假设旧的相对 TIL/ANI 引用有效。
- 选中 TIL 可跳转其原文件。通行格绘制和修改 TIL 内容本身作为后续增强；首版保留已有碰撞预览，不扩展为完整碰撞绘制工具。

### 6.3 全局实体与动画/特效

- 被动对象、怪物、NPC 分别使用其 `.lst`；展示编号、定义路径、可用名称和待机预览。名称不能解码时仍能按编号/路径选择。
- 点击添加后进入放置模式，点击场景落点提交。默认生成该格式已验证的最小原生记录；怪物的等级、复制类型、普通/精英/Boss 等参数可在属性中调整，不能把第二个字段误标为固定数量。
- 支持普通与已识别特殊被动对象的坐标/内容编辑；复制特殊对象需同时复制完整负载。
- 动画以原生 `[animation]` / `[background animation]` 表达，提供层、X/Y/Z 和背景顺序设置；保留 flat / `[ani info]` 两种背景结构。
- 特效首版包含 ANI 动画、背景 ANI、已识别的粒子工厂 OBJ。任意 PTL 文件没有已核实的 MAP 直接标签时，不编造一个新字段来放置它；仍可通过原有资源预览检查。
- 全局对象的 layer、ANI 或定义被共享时，在当前 MAP 中只暴露原放置格式真正支持的属性；修改共享定义必须跳转原文件并提示影响范围，不能生成客户端不读取的实例字段。
- 怪物新增/复制/删除必须同步已识别的 `[monster specific AI]` 等按顺序对应的辅助记录。遇到无法关联的变体时，对该类结构操作禁用并指出原因；安全确定的坐标字段仍可编辑。

## 7. 深渊机制与编辑边界

### 7.1 只读调查结果

调查工具：`build/research/HellDungeonAudit.java`，仅通过 PvfArchive 读取，未创建或修改用户草稿。原始报告和抽取片段位于 `build/research/hell-audit-20261026-*-v2/`，这些游戏数据不提交仓库。

| DNF_Single | 1 | 1 | 0 |
| 70S2 | 347 | 342 | 77 |
| DOF86 | 449 | 441 | 93 |
| 100 级 | 460 | 444 | 107 |

这些是脚本统计，不是游戏内已验证可进入深渊的副本数量。失败为所选编码不能无损解码等已有问题，报告保留具体文件与原因。

确定的配置关系：

- `[hell dungeon]`：DGN 的深渊能力标志。
- `[seal door map index]`：通过 map.lst 指向深渊专用 MAP。
- `[seal door pos]`：副本网格坐标，不是深渊柱在 MAP 内的像素位置，也不是普通终点 Boss 坐标。
- 深渊模式下，用指定 MAP 替换该坐标的普通房间；保持其副本拓扑语境。
- ACT1 抽查 `60001` 的特殊被动对象直接含 `[monster] 1050 ...`；70S2 / 86 / 100 级抽查含 `[hellparty]` 列表，三元组为组索引、相对权重、组号，引用 `etc/hellparty.etc`。
- 科勒发电站样本的深渊 MAP 为 `60067`，位置 `(4,0)`，普通 Boss 为 `(4,1)`；两者须独立保存与显示。
- 新版样本中的 `[escape hell] 1` 表示某套 maze 不出现深渊。不能把每套 maze 共享为一份房间替换配置，也不能忽略这个排除标志。
- `[hit count]`、`[seal door appear rate]` 及部分旧版 `[hell coin limit]` 有版本差异。ACT1 实际有 4 项 hit count，新版样本有 5 项；保留原数量，不擅自统一长度或将出现参数包装成未经确认的百分比。

本地依据还包括 DFLegacy 的 `DungeonCatalog.cs` / `DungeonRunState.cs` 房间替换代码，以及既有原生客户端 `build/client-coordinate-evidence/dungeon-load.txt` 的标签读取证据。DFLegacy 的模拟行为不是所有新版本客户端的完整规范。

### 7.2 用户看到的深渊设置

- DGN 全局区显示“允许深渊模式”；每套布局显示是否参与深渊、其替换房间坐标与深渊 MAP。按源作用域保留配置；全局能力与每布局替换项不混存。
- 在网格里把所选房间设置为深渊点；普通/Boss 候选保持原样。“普通 / 深渊”预览切换显示该点替换前后实际 MAP，并保留整套连接。
- 支持 `[escape hell]` 的布局显示“当前布局不出现深渊”；不启用的布局不会误显示已生效深渊图标。
- “编辑深渊 MAP”打开真实 MAP 标签，选中深渊柱，编辑柱子位置和本地图的召唤配置。旧版显示直接怪物配置，新版显示 hellparty 引用列表；不自动迁移两种格式。
- 全局 hellparty 组定义可查看与跳转，首版不提供一个会悄悄影响所有地图的“本房间全局组修改”表单。用户可在原 ETC 的代码编辑器显式修改。
- 高级项按源字段列出 hit count 和出现参数及旧版已有字段，准确语义未证实前保留原值、数量和标签；基础深渊房位置/MAP 编辑不依赖这些参数的默认猜测。新启用深渊采用同包已有深渊配置作为模板并展示将写入的参数。
- 门票、前置任务及世界地图按钮属于 WDM/任务/服务端的另一层配置；提供关联诊断和跳转，不把打开 DGN 开关描述为已经解决全部游戏入口条件。

## 8. 文档模型、源片段修改与兼容

建议增加一个不依赖 IntelliJ 的 `pvf-scene-edit` 模块：维护可编辑记录、源位置、命令验证和最小文本补丁；复用 pvf-preview 的语义与坐标规则，避免再写一套渲染逻辑。UI 适配留在 pvf-product；PVF 编解码和事务仍归 pvf-workspace。模块划分是实现方的选择，可在计划中细化类名。

解析结果须同时保留：原标签拼写/语言、token 类型、字符串引用方式、数字源范围、整个记录范围、所属 maze/区段、文档版本与诊断。不用物理行作为二进制投影中多条记录的身份。

写入原则：

1. 坐标或属性修改尽量只替换相应 token；添加/删除记录使用明确的记录边界，保留周围注释、未知字段、换行和顺序。
2. 未编辑的文本范围逐字符保持。未知二进制 token（如 `@9/@10`）继续交给现有编解码器保留；不能转成普通字符串。
3. 文本 PVF、B0 D0 投影、韩文别名和 nested ani info 都先判定是否可可靠编辑。无法无损解码、混合换行或不可识别二进制结构继续原有只读策略。
4. 界面局部只读：一个未知字段不应令全部 MAP 永久不可编辑；但记录边界无法确定时，不能尝试猜测后回写。
5. 任一命令先完成解析、验证和补丁预备，再在写命令中确认版本并提交；源文档变化导致的失败保持文档不变。
6. 编码回写和字符串表新增使用当前 PvfWorkspace/BinaryScriptCodec；仅打开、切换视图或渲染不产生草稿变更。

## 9. 引用、共享文件与事务

- 所有索引与资源选择来自当前挂载 PVF、草稿和已打开文档的合并快照。新增或删除文件后局部失效；大列表分页/后台索引，UI 线程不全量加载视觉。
- 同一个 MAP 或深渊 MAP 被多个房间/副本引用时，属性区展示已知引用范围；反向索引尚未完成时明确“引用统计未完成”，不能断言只影响当前房间。
- “复制 MAP 并用于此房间”默认复制到同目录，分配 map.lst 未占用的新编号并显示路径；用户可以改名。跨目录复制必须同步重定位相对引用并验证。
- 克隆、map.lst 注册、DGN 绑定是一项跨文件命令。预先保存相关文档/结构的 before/after 状态，新增条目与文字编辑通过一个可撤销工作区事务发布；失败全回滚，不能残留半注册的 MAP。
- 不得把未保存的旧 map.lst 或 DGN 文档静默覆盖；冲突时保留现状，取消该命令并重新预备。
- 删除 DGN 房间不删除共享 MAP、ANI、TIL 或全局列表条目。源 PVF 的只读与导出备份规则不变。

## 10. 会话与性能

- 以虚拟路径恢复显示模式、分屏比例、当前布局/房间、画布相机/缩放及对象选择；对象无法再匹配时清除选择，不猜到另一条记录。
- 代码编辑器的光标和滚动沿用已有恢复逻辑；会话格式扩展需兼容旧版文件，不丢弃既有标签。正文仍仅属于草稿系统。
- 一个 Session 只有一个 Document/Undo 链。切换、后台预览与引用索引使用不可变快照，解析/渲染版本过期则丢弃。
- 鼠标移动不触发全 PVF 索引或整包重新解析；拖动的中间帧不写草稿，数值输入适当合并撤销。
- 保留加载进度、取消与 UI 响应；不能因任务取消中断共享 FileChannel 并卸载整个 PVF。

## 11. 验证与交付门槛

不以草图中的模拟交互作为产品验收。

### 核心与兼容

- 选取文本与二进制投影夹具，覆盖同一行多实体、注释/引号中的标签、未知 token、韩文别名、多 maze、nested 背景。
- 对每种图形命令验证：精确预期配置、未编辑范围不变、重复编号冲突处理、撤销/重做、失败不留部分修改。
- 地块序列与扩展行、monster specific AI 对齐、特殊对象的完整负载、普通/Boss 候选、对称连接及每布局深渊作用域均有实质测试。
- 克隆/注册/绑定的失败、保存失败、取消和撤销不能留下孤立文件或引用；二进制字符串表事务一并验证。

### 实际桌面操作

- 可视化、代码、分屏反复切换，验证未保存内容、Ctrl+Z/重做、光标/滚动、选择/相机和标签会话恢复。
- 代码输入临时错误与代码/拖动并发时，验证陈旧画面不能覆盖新文档；错误修好后重新同步。
- 在真实 NPK/IMG 画面完成房间创建、MAP 指定、连接、起点/Boss 与深渊替换预览，并进入 MAP 添加 TIL、怪物、对象和 ANI。
- 小窗口至少覆盖 1024×720 与已有 1264×811 场景；代码入口、属性与返回来源副本始终可达。

### 真实包与输出

- ACT1、DNF_Single、70S2、DOF86、100 级各选受支持配置检查，不把某个样本没有深渊当作解码失败。
- 在新的隔离工作区导出，独立回读并比较目标字段、引用和未改条目；保留源包 SHA-256 不变的证据。
- 100 级样本的导出/游戏加载当前未完整验收，新功能不得仅凭读取成功宣称该版本已可正常进游戏。
- 原有测试、独立验证和产品冒烟继续通过。游戏内测试只在隔离副本且取得本地可用环境时执行，未执行则明确列出。
- 更新用户文档、变更记录和 Windows 交付包。版本号、正式 GitHub Release/上传由后续任务授权与既有发布约定决定，本文不预先声明已发布。

## 12. 留给实施计划的事项

实现者可决定具体类名、选中框样式、资源缩略图布局、索引缓存粒度、分屏默认比例，以及在上述范围内的拆分顺序。建议先完成文档桥接和安全补丁，再做 DGN、MAP 工具和深渊配置，最后完成多版本回写与桌面验收。
