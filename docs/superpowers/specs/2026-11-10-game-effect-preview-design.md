# 装备、装扮与技能的游戏效果预览设计

日期：2026-11-10。状态：方案 A、设计范围及“预览优先 / 代码分屏”布局已获用户确认（“可以”）；开始实施。

代码基线：完整桌面源码所在工作树 `G:/Game/DNF_ACT1/PVFStudio/.worktrees/map-dungeon-editor`，提交 `9d03b91`，产品版本字段为 0.14.7。主目录存在的 `pvf-product` 未提交删除不属于本次工作，不恢复、不纳入提交。

## 1. 意图与已确定的选择

用户希望优化 PVFStudio，在选中装备、装扮、技能等配置时，直观看到游戏中的呈现和对应动画，减少手工查找素材及进入游戏逐个试看的成本。四张截图提供激光炮、称号、护甲和武器属性及效果的参考。

用户已选择方案 A：编辑器内组合预览，用游戏内效果对照校准。Java / Swing / IntelliJ Platform、现有 PVF 工作区及 NPK/IMG 渲染器继续作为实现基础，这是实现方根据现有工程作出的选择。

以下功能范围、界面安排和分阶段验收为实现方提案，随本设计一起确认；用户没有逐项指定全部细节。

## 2. 方案比较

| 方案 | 收益 | 成本及边界 | 选择 |
| --- | --- | --- | --- |
| A：编辑器内合成角色、动作和特效 | 选择配置立即预览，可消费未保存修改，无需游戏在线 | 须解析角色装配并补充有证据的技能时序；完整战斗依赖不能由素材本身推导 | 用户已选择 |
| B：联动真实客户端执行 | 可观察真实施放、命中及运行时触发 | 依赖运行环境、资源加载和测试场景，不能直接响应尚未导出的编辑内容；联动接口须另行验证 | 本次不采用 |

方案 A 的游戏对照属于验收手段，不是嵌入或自动启动游戏客户端的功能。

## 3. 现有能力与已检查的缺口

- `pvf-preview/ResourceScript.java` 已读取带帧号的 IMG、ANI 和 PTL 引用；预加载 IMG 路径本身没有帧号，不能直接组成技能。
- `AnimationTimeline`、`PreviewRenderer`、`NpkResources` 已支持按时间采样、原点、图片裁剪、透明及部分混合，资源按需加载并有限缓存。
- `EntityScript` / `ScenePreview` 已支持地图实体初始视觉及部分怪物装备，但没有玩家的完整穿戴模型。
- 桌面 `ResourcePreviewPanel` 已有后台任务、过期结果检查、播放、逐帧、倍速、缩放和资源目录关联，当前 EQU/SKL 以直接资源引用为主。
- 实际 ACT1 装扮 `auniform_wtsummer.equ` 含两组 `[layer variation]`、`<include>` 和 `[variation]`；共享 `gunner.lay` 用 `%s` 指向不同动作。须沿 EQU → LAY → ANI → IMG 展开，保留前后图层。
- `character/character.lst` 列出剑士、格斗家、枪手、魔法师、圣职者；CHR 定义基本和扩展动作，须用于职业和动作选择。
- 激光炮 `skill/gunner/laserrifle.skl` 有等级参数、施放前延迟、射程、图标及预加载素材，没有声明完整施放动画时序。其关联不能靠文件名相似度确认。
- 称号样本含 `[custom animation]`；条件效果样本含 `[if] / [then]`，文字说明与可执行效果须分别处理。

## 4. 用户可见行为

### 4.1 打开配置

为可识别的 EQU、SKL、STK 提供默认的中央“效果预览”视图，保留代码和分屏切换，以及代码模式下现有的资源引用预览。左侧继续文件树，中央角色/特效画布，右侧游戏说明、穿戴搭配及资源页，底部播放与时间轴。用户已查看两种可点击布局并确认采用预览优先。继续使用现有搜索、代码编辑和草稿，不另建配置副本。

“游戏效果”包含：

1. 配置摘要及游戏样式属性说明：图标、名称、品质颜色、职业与等级要求、已识别属性、技能等级参数、说明和触发条件。
2. 角色或效果画布：完整身体加当前选中物品，按需显示称号、动作及特效；没有可视内容时给出具体原因。
3. 与当前对象相关的控制：职业、动作、朝向、技能等级、重播，以及已有播放/暂停、逐帧、倍速、时间轴与缩放。

低频设置、装配槽和资源诊断可折叠，首屏保留画布和基本播放操作；在 1024×720 与 1264×811 下检查控件可达和文本滚动。未知字段保留在代码和诊断中。

### 4.2 装备与装扮

- 通过职业、装备类型和实际装配字段选择角色；多职业物品允许切换适用职业。
- 以该版本实际默认身体/装扮为基底，当前物品替换所属槽。用户可从同包选择其他装备或装扮组成预览套装，也可重置。
- 首版覆盖 ACT1 五职业的身体和通用穿戴解析，以及包内存在的待机、移动、普通攻击、跳跃动作；只列当前职业可解析的动作。
- 读取 variation、layer variation、include、图层、遮挡及原点；身体、武器和装扮在统一角色时间中合成。部件帧数不同时保持各自原有时间，不按数组下标强行对齐。
- 装配姿态、层序及隐藏规则由脚本或核对过的版本规则决定；未知规则给出局部诊断，保留可确定的部件。
- 普通护甲、首饰或其他没有独立穿戴外观的物品显示属性及已有图标，并说明“配置未定义独立穿戴外观”。是否改变角色外观由配置及经核对的客户端规则决定。
- 称号使用 custom animation 合成到角色；头顶锚点须对照客户端，不能随画布缩放漂移。

### 4.3 技能

- 技能等级读取实际上限并影响已核实的等级参数。属性说明显示当前选择等级的 MP、冷却和其他已解析项目；不推导缺失的伤害公式。
- 对具有显式动作/特效关系的配置自动跟进引用；对 ACT1 内置施放流程建立按版本及职业、技能 ID 区分的效果配方。
- 配方记录阶段、角色动作、相对锚点、开始与结束时间、弹道/平铺规则及其参数来源，同时记录证据出处与已验证范围。
- 首个必须完成的技能闭环是截图中的激光炮：角色前摇、枪口、光束、末端/消散；普通和蓄力分支仅在资源及机制核对后开放。静态延迟和射程应来自当前脚本。
- 验证阶段再选至少一种其他职业的显式 ANI/PTL 或被动对象技能，检查通用引用路径和组合模型，避免整个系统只能演示激光炮。
- 可以显示单独素材、部分组合或完整已验证演示，各状态明确区分。没有已确认配方时列出可播放的关联资源及缺口，不能把预加载图片按顺序播放后标为完整技能。
- 该阶段交付通用模型与有证据的首批配方；不承诺一次覆盖全部职业的每一个技能。支持清单须列出实际覆盖项和未覆盖项。

### 4.4 装备触发与其他物品

- 读取已识别的 if/then 条件、概率、冷却、持续时间、目标和效果；显示说明与脚本定义的差异，不用说明文字替代配置。
- 能确定视觉引用的效果提供“演示触发”及重播，直接展示该视觉；演示不会把触发概率改写成必定触发的实际游戏规则。
- 纯属性增益显示条件与增益说明；依赖未识别客户端逻辑的效果列出原因，不生成猜测特效。
- 截图中的“吞日者”武器特效作为必须调查的验收项：先确定当前包的准确物品 ID、定义与相关对象。若流程由客户端实现，需核对相同版本代码/实拍并补充配方；若样本不含此物品，报告该缺失，不能悄悄换一个物品宣称通过。
- STK 等其他物品复用属性说明和显式效果引用；首版不构建独立消耗品战斗系统。

### 4.5 属性说明的精度

- 解析当前 PVF 的本地化引用（例如 `<12::name_16285>`）及对应字符串目录；使用选定编码和当前覆盖层，缺失时保留键与诊断。
- 属性面板使用接近游戏的品质色、分组和排版。显示值来自配置，不把截图 OCR 数值当作新规则。
- PVF 没有某件运行时实例的随机品级、强化、耐久或角色最终属性。范围值、基础值与需要上下文的数值须明确标识，不能伪装成截图中某个角色的最终面板。
- 预览职业、技能等级和搭配属于预览设置，不自动写回 EQU/SKL。

## 5. 数据和渲染结构

在现有模块中增加职责明确、无 IntelliJ 依赖的预览模型；具体类名由实现者决定。

- 配置解析层：读取 CHR、EQU、LAY、技能及物品字段、本地化、include 和资源引用，输出带路径及诊断的类型化模型。
- 装配层：生成职业身体、槽位替换、variation、图层和遮挡后的绘制轨道。路径仅在当前 PVF / NPK 索引解析，规范化大小写和分隔符；禁止读任意文件系统 include。
- 效果层：把显式引用和版本配方转换为时间轨道，处理开始、结束、运动、相对位置和循环。复用现有动画与粒子采样。
- 渲染层：复用图片解码、原点和 Prepared 绘制，不复制一套 IMG 解码器。多轨共享绝对毫秒时钟，任意 seek 后结果可复现。
- 桌面层：绑定当前 Source、文档/资源代数、控制项和后台结果。编辑更改继续按现有短延迟刷新，旧任务不能覆盖新的文件或选择。

预览读取顺序：当前未保存 Document 快照 → 已保存草稿 → 原包。依赖 CHR/LAY/ANI/STR 的修改也能失效相应缓存，不能只监听顶层 EQU/SKL。

缓存键包括工作区/包身份、文本版本、资源目录代数、职业、装配、动作与技能等级。PVF 和 NPK I/O、依赖解析、扫描与像素准备在后台执行；UI 线程仅接受结果并绘制。

递归 include 和效果引用必须有循环检测、深度、文件数、轨道数及内存上限。具体上限由实现者结合现有预算确定并记录；超限时保留诊断，不能卡死 UI。全库索引按需/后台建立，不在每次播放或选中控件时重扫整个 PVF。

## 6. 版本、证据与范围

首个完整验收版本为用户截图对应的 ACT1。同一预览必须绑定配套 PVF、NPK 和版本，记录样本摘要。优先检查本机已有 ACT1 输入；其他容器版本继续原有直接资源预览。

版本专用配方只有在版本特征、所需配置与资源满足时启用；不能仅按技能 ID 把 ACT1 的内置规则应用到 70/86/100 等样本。未知版本显示支持范围及可确定的资源。

游戏内对照至少覆盖穿戴层序/颜色、称号锚点、普通攻击、激光炮阶段及已完成的装备触发。用户截图是外观与说明参考，其中没有完整动画时间证据。动画时序须另行获取相同版本实拍或可检查的客户端依据，不能由静态截图宣称像素或时序一致。

原生资料、资源、录屏和截图保存在忽略的 build 或仓库外。源码仅保留独立实现、规则数据及不含游戏素材的证据索引。

## 7. 实施阶段和完成边界

1. 角色装配与说明：本地化、EQU/LAY/include、五职业身体/基本动作、搭配槽、称号及当前草稿联动。
2. 技能与触发：通用多轨时间模型，激光炮闭环、另一个职业的代表技能，以及“吞日者”特效调查和可证实实现。
3. 桌面整合及游戏对照：控制项、小窗口、异常/版本诊断、性能采样、回归、可运行便携构建及证据报告。

这些阶段组成同一次功能交付；阶段一完成不能被报告为整项任务完成。若客户端专用逻辑或样本缺失阻碍某个要求，须明确列为未完成项，并给出已有依据和下一步。

成功标准：用户可在可运行 PVFStudio 中选择有支持的装备/装扮/技能，看到真实资源合成的角色与动画，调整动作/等级/播放，并在编辑脚本后观察更新；所有宣称支持的首批案例都有具体结果与证据，未覆盖项清晰可见。

## 8. 验证与交付

- 解析与像素测试：多次 include、相对路径、循环、variation、前后图层、hide layer、左右朝向、不同帧时长、称号锚点及缺失部件。
- 效果测试：阶段开始/结束、暂停、倍速、重播、前后 seek、延迟/射程参数修改、未知技能配方及版本不匹配。
- 工作台验证：实际选择 EQU/SKL/STK、五职业基本动作、完整搭配、未保存的顶层与依赖修改、快速切标签、资源重选、后台过期结果和小窗口。
- 游戏对照：记录实际输入、观察内容、时间点及差异；区分“配置解析通过”“离线绘制通过”和“游戏对照通过”。护甲无外观和纯属性增益也是有效且必须解释的结果。
- 回归：运行工程现有相关 JVM/Python 检查及桌面产品检查，覆盖 MAP/DGN、ANI/PTL、草稿和导出行为。纯预览不制造脚本修改；原始游戏资源在本轮前后核对摘要。
- 性能：记录相同机器与样本的首次加载、缓存后切动作、播放和峰值内存；检查窗口持续可交互、后台任务可失效和缓存有界，不以未经测量的速度承诺替代结果。
- 交付可运行的本地便携构建、操作说明、支持矩阵、游戏对照/未完成项报告。外部发布和客户端资源替换不由本设计自动授权。
