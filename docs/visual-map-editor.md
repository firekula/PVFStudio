# MAP 与 DGN 可视化编辑（0.14.1 本地修复版）

打开 PVF 后双击 `.map` 或 `.dgn`。标签右上角可切换 **代码 / 分屏 / 设计**；三种视图共用同一文档、撤销历史和草稿。Ctrl+S 保存独立草稿，导出才生成修改后的新 PVF。原包始终只读。

## MAP

左侧资源来自当前 PVF、草稿和打开的文档。TIL / ANI 范围是当前 MAP 同目录及其子目录；NPC、怪物和被动对象按全局列表编号。搜索编号或路径，选择后读取名称、原生地块类型及缩略图；资源目录未载入时仍可查看脚本信息。特效候选属于被动对象，识别到粒子工厂后沿原引用渲染，工具不会增加虚构的 MAP PTL 字段。

选择资源后点击“添加到中心”或“点击画布添加”。左键选择 / 拖动对象，重复点击轮换重叠对象；中键或按住空格拖动平移，滚轮缩放，Esc 取消。拖动改变 X / Y，保留 Z；松开形成一次撤销操作。逻辑对象即使没有图像也保留选择锚点。属性面板可复制、删除、定位源码、打开全局定义。全局定义的改动会影响所有引用者。

基础地块追加为一列；已有扩展行时须明确选择每行的新单元。识别为扩展 TIL 的资源会让你逐单元确认新扩展行。地块序列窗口支持直接编辑基础 / 扩展引用、移动整列、替换所选单元和删除整列；扩展行必须与基础列等宽。添加、删除或移动列会同步调整扩展行。

容器 / 封印对象按原格式编辑内容：旧版直接怪物参数与新版 hellparty 列表分别保留，不自动互转。需要修改组定义时显式打开 `etc/hellparty.etc` 的代码编辑器。

MAP 可能被多个房间或副本共享。目前显示“引用统计未完成”，不要把直接修改视为只作用于当前房间。需要独立变体时从 DGN 使用同目录克隆与绑定。

## DGN

主区域只显示一个地图预览，房间网格位于右侧设置区。点击网格选房间。在空格填写 MAP 候选后“创建房间 / 应用候选”。勾选通路会同步修改相邻房间的反向连接；新连接须先有可验证的原生门坐标。自动池未明确选择时，可先为两端指定 MAP。检查项会提示 MAP 类型、Boss 怪物识别及门坐标问题，可跳转原 MAP 源码，不会悄悄改写共享文件。

没有显式 MAP 列表的房间会显示实际自动选图池，并标注其来源。可以直接修改候选或通过选择按钮指定；应用时只把修改过的自动字段固定到本房间，未修改的字段保持自动。

起点与 Boss 均可有多个候选，也可用“仅此房为起点 / Boss”。新建、复制或切换布局后，房间设置只作用于当前布局。缩小尺寸会列出被裁掉的房间和引用并要求确认；MAP 文件本身保留。新建的不可达房间可以保存草稿，导出前须完成连接。原有单房 AA 教程起点仍可编辑。

“克隆 MAP 并绑定”复制到同目录，保留 TIL / ANI 相对引用，分配未用编号，更新 `map/map.lst` 及当前普通 / Boss / 深渊绑定。三处一起发布或回滚，Ctrl+Z / Ctrl+Y 整体撤销 / 重做。相关文档在提交期间冻结并核对版本；新 MAP 还有后续编辑时须先撤销那些编辑。

## 深渊房的机制与设置

现有样本表明：副本全局允许深渊后，当前 maze 的封印坐标使用专用 MAP 替换该位置的普通 MAP。深渊位置与普通 Boss 位置独立；`escape hell` 是单套布局的排除标志。科勒发电站样本中封印 MAP 为 60067、位置 (4,0)，普通 Boss 为 (4,1)。

在网格选好位置，再设置封印 MAP 和“设为当前房间”。普通 / 深渊预览只切换画面，不修改配置；未启用或被排除时不显示生效 H 标记。编辑深渊 MAP 会打开真实标签并优先选择识别到的 hellparty 封印对象，旧版回退到直接怪物容器；返回副本按钮保留来源。

新启用时从当前 PVF 的已有深渊副本选择模板，界面显示将应用的原始参数。已有击打参数保留其四项或五项数量；出现率单位尚未证实，直接编辑原始值。金币限制仅在已有字段或经同包模板证实时引入。门票、任务、WDM 入口及服务端条件仍需各自配置，DGN 开关不代表这些条件已完成。

## 兼容与数据安全

未编辑的源码片段、未知字段、注释和不透明二进制 token 保留。源码尚未完成或记录边界不可靠时，受影响图形写入禁用；最后有效画面可继续查看。混合 CRLF / LF / CR 文本可以编辑，保存时保留未改动片段的原始行尾；新增换行使用该文档原有主要格式。无法可靠解码及不支持的二进制结构沿用只读策略。固定 warroom 布局可在代码中查看，不自动转换成 maze。

视图模式、分屏比例、布局 / 房间、相机 / 缩放及 MAP 选中对象写入兼容旧格式的会话元数据。对象身份同时核对原生 token 内容；恢复时无法确定则清空选择。相同路径不会再打开第二份文档。

## 本地验证

`validation/VisualSceneEditAudit.java` 使用显式 PVF、全新输出目录和编码，执行原生 MAP / DGN 编辑、深渊参数修改、保存、重开、导出和回读。`validation/verify_visual_scene.py` 通过独立 Python 容器解析器逐项校验导出及未修改数据，并独立解码 B0 token，核对源码语义和原包 SHA-256。

本地 ACT1（GBK）、DNF_Single（MS949）、70S2 / 86 / 100（Big5）样本全部完成上述读写校验。单机样本没有深渊配置，其余四份覆盖深渊修改。原生桌面 smoke 另检查画布拖动、版本竞争、视图 / 标签生命周期、普通与深渊真实资源预览及跨文件撤销。

这些是编辑器和文件格式证据。没有把 100 级文件的读写 / 预览结果表述为已通过对应原生游戏内加载；也不模拟服务器随机出图、AI 或战斗。

已知小问题：将场景文件改成普通扩展名后，请使用代码模式；此时遗留的设计 / 分屏按钮可能报错，改回 MAP / DGN 扩展名可恢复。独立审阅与修复证据见 [验证记录](visual-editor-validation-2026-10-26.md)。
